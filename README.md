Моя система авторизации и аутентификации (djangoDRF)

Всего у меня 2 таблицы в БД - (users и roles)
У users поля - 
id email(почта) password(пароль в хешированном виде) name surname patronimic (Фамилия Имя Отчество) role (ссылка на роль из roles) is_active (мягкое удаление)

У roles поля - 
id role(1 буква название роли) get(получение всех записей пользователей, ролей, продуктов, заказов) postself(изменение себя) postusers(изменение других пользователей и продуктов) postroles(изменение ролей и заказов) delete (удаление из бд) - всё boolean

3 приложения - api(основная программа) myadmin(админка) business(mock)
в апи содержатся модели, миделвейр, класс профиля и прочие viuwы связанные с ним типа регистрации входа и выхода
в myadmin только viuwы для управления записями, можно получать, удалять, менять, если есть соответствующие привилегии
в business заглушка для заказов и продуктов (по хорошему нужны новые поля в roles для работы с ними)

Аутентификация через POST запрос на страницу api/login,
при успехе формируется jwt token и выдаётся cookie с ним, 
последующая авторизация происходит через него, или можно через bearer, обрабатывается своим middleware.
Разрешения в основном проверяются через класс RoleBasedPermission наследующийся от permissions.BasePermission,
кроме случаев, когда надо проверять доступ к конкретному объекту, тогда проверка в коде (например когда postself и надо узнать меняем ли мы именно себя).

В миграции приложения api вшиты дефолтные роли и пользователи (нет пароля для гостя, пароль 1111111 для остальных), просто укажите в settings данные бд и мигрируйте
